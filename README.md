## 🎰 연금복권720+ 규칙

티켓은 **조(1~5)** + **여섯 자리 숫자(000000~999999)** 입니다.
추첨은 **매주 목요일 저녁 7시 5분**, 판매 마감은 **목요일 오후 5시**입니다.

| 등수 | 조건 | 당첨금 |
|---|---|---|
| 1등 | 조 일치 + 여섯 자리 전부 일치 | 매월 700만원 × 20년 |
| 2등 | 조 무관 + 여섯 자리 전부 일치 | 매월 100만원 × 10년 |
| 보너스 | 조 무관 + 보너스 여섯 자리 일치 | 매월 100만원 × 10년 |
| 3등 | 뒤 5자리 | 100만원 |
| 4등 | 뒤 4자리 | 10만원 |
| 5등 | 뒤 3자리 | 5만원 |
| 6등 | 뒤 2자리 | 5천원 |
| 7등 | 뒤 1자리 | 1천원 |

판정은 위에서부터 먼저 맞는 것 하나만 적용합니다. `wnRnkVl` 이 앞자리 0을 떼고 오기 때문에
자릿수를 채워 비교하지 않고 **뒤에서부터 잘라** 비교합니다.

## 📐 번호 추천 — 근거를 밝힌 3가지

로또와 달리 연금복권은 **당첨금이 정액**이라 "덜 붐비는 조합" 같은 논리가 성립하지 않습니다.
대신 **확률 구조 자체에서 증명되는 것**만 넣었습니다.

| 방식 | 방법 | 실제 효과 |
|---|---|---|
| 완전 무작위 | 조·번호 균등 | 기준선. 1등은 500만분의 1 |
| **끝자리 분산** | 5장의 마지막 자리를 서로 다르게 | 7등 하나라도 맞을 확률 **50% vs 40.95%** |
| 번호 하나로 다섯 조 | 같은 번호를 1~5조에 | 기대값 동일, **되면 1등 1장 + 2등 4장** |

끝자리 분산이 정확히 50%인 이유: 7등은 마지막 한 자리만 맞으면 되고, 끝자리가 서로 다른 5장이면
0~9 중 5개를 덮으므로 정확히 5/10 입니다. 아무렇게나 5장이면 `1 − 0.9⁵ = 40.95%` 입니다.

> 어느 방식도 1등 확률을 높이지 못한다는 고지를 화면 상단에 고정으로 띄웁니다.

## 🔔 알림 시각

판매 마감(목 17시)과 추첨(목 19시 5분)에 맞췄습니다. 앱인토스 푸시는 야간 방해금지가 있어
21시 이후로는 발송되지 않는데, 연금복권은 추첨이 이르러 여유가 있습니다.

**구매 알림** — 아직 살 시간이 남은 시각만

|---|---|---|
| `pension-alarm-buy-wed1900` | 수요일 저녁 7시 | 113938 |
| `pension-alarm-buy-thu1000` | 목요일 오전 10시 | 113939 |
| `pension-alarm-buy-thu1400` | 목요일 오후 2시 | 113945 |
| `pension-alarm-buy-thu1600` | 목요일 오후 4시 (마감 1시간 전) | 113946 |

**확인 알림** — 추첨 뒤

| 발송 코드 | 시각 | agreementId |
|---|---|---|
| `pension-alarm-check-thu2000` | 목요일 저녁 8시 | 113947 |
| `pension-alarm-check-fri0800` | 금요일 오전 8시 | 113948 |
| `pension-alarm-check-fri1000` | 금요일 오전 10시 | 113949 |

> 앱은 **동의만 받습니다.** 실제 발송은 콘솔 스마트 발송에 위 코드로 템플릿을 만들어야 동작하고,
> 그 템플릿은 앱이 **출시(`status=OPEN`)된 뒤에만** 만들 수 있습니다.

## 📡 당첨번호 데이터

동행복권 **공식** 엔드포인트를 그대로 씁니다. CORS 가 열려 있어 백엔드가 필요 없습니다.

```
최신 회차  GET https://www.dhlottery.co.kr/pt720/selectPstPt720Info.do
특정 회차  GET .../selectPstPt720Info.do?srchPsltEpsd=327   ← 주변 회차가 섞여 오므로 psltEpsd 로 걸러냄
```

응답 `data.result[]` 의 `wnSqNo` 가 등수를 가릅니다 — `1`=1등(이때만 `wnBndNo` 가 조), `2`=2등,
`3~7`=3~7등, `21`=보너스.

| 화면 하단 고정 (앱 전체 1개) | 문구 강조형 배너 | 30초 | `ait.v2.live.5edccd21f81a4e8b` |
| 각 화면 본문 맨 아래 | 이미지 강조형 배너 | 30초 | `ait.v2.live.b5625de4b9a44da7` |

화면이 가려져 있는 동안에는 갱신을 멈춥니다. 이미지형 배너 자리는 소재가 잘리지 않도록
고정 높이가 아니라 최소 높이로 잡았습니다.

## 🚀 개발

```bash
npm install
npm run dev            # 브라우저 (광고·알림은 미지원 환경으로 자동 우회)
npm run check:pension  # 등수 판정 · 추첨시각 계산 · 추천 방식 자체 점검
npm run typecheck
npm run build          # vite build + ait build → pension-alarm.ait
npm run deploy
```

`.env.example` 를 `.env` 로 복사하고 콘솔에서 발급받은 광고그룹 ID를 채우세요.
비워두면 배너는 그려지지 않고 리워드 광고는 즉시 통과해서, 브라우저 개발이 끊기지 않습니다.
`VITE_` 변수는 빌드 시점에 번들로 구워지니 값을 바꾸면 반드시 다시 빌드하세요.
